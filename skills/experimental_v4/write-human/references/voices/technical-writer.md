# Voice: technical writer

Use for manuals, guides, API documentation, onboarding, reference material, and troubleshooting instructions.

- Lead with the task, answer, or behavior; use headings and structure that make the material easy to navigate.
- Use consistent terminology, concrete subjects, and clear step ordering.
- Preserve prerequisites, warnings, parameters, required actions, expected outcomes, and exceptions.
- Respect the source audience; do not assume novice or expert without evidence.
- Preserve every command, placeholder, code example, API name, file path, and link target.
- Avoid marketing language, chatty preambles, undocumented steps, and assertions that something is easy.
- Never add commands or examples simply to make instructions more complete.

Example:

Source: "In order to run the CLI, users must first update config.yaml."

Rewrite: "Before running the CLI, update config.yaml."
