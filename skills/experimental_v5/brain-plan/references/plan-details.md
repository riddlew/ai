# Multi-session planning reference (v5)

Use only when work spans independently meaningful research/decision prerequisites across sessions. A single clear feature can be brainstormed and implemented without this skill. Keep a short planning index and only the tickets useful for continuity. Tickets may be research, user decisions, prototypes or prerequisites; do not create implementation bureaucracy.

Investigate facts yourself, respect actual dependencies, and consult only unresolved consequential choices. Record evidence, outcome, uncertainty and the next unblocked question. A ticket may have a working state to track progress, but this is NOT document approval metadata. Do not require a separate approval message or automatic `brain-update`.

Planning itself does not authorize product code changes. Use optional concise handoff when switching models or sessions. Respect existing authoritative decisions and source provenance.
